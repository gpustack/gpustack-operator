Engine Compatibility

Verify engine, Mooncake and transport compatibility before choosing container images. Engines below the listed minimums are unsupported. Upgrade before diagnosing failures on an older engine release.

The matrix covers aggregated serving, prefill/decode (PD) and encode/prefill/decode (EPD) configurations.

Engine image requirements

  • Image floor: There is no engine.version field. Roles run roles[].image or spec.engine.image (Role images ), and admission never checks the tag. An image below the floor fails at startup (ImagePullBackOff or unknown-flag exit).
  • Render flag: Non-Encode vLLM deployments behind llm-d-router need --enable-scale-out starting at vLLM 0.30.0 or vLLM-Ascend 0.30.0rc1 (Router token counting ). Earlier 0.29.0/0.23.0 floors predate that dependency.
  • Mooncake client and store: Each runner image embeds its Mooncake client (ROCm images compile their own and are unverified). Match KVCacheBackend members to the client’s minor line (Version compatibility ).
  • Direct transport defaults: Listed runs moved KV over tcp, or ascend on vLLM-Ascend (which does not support direct tcp; see Role links and connectors ).
  • Not verified: Means no live hardware run, not a refusal or known failure.
  • Encoder floor: Pick an image meeting the supported serving configurations floor (0.30.0 for NVIDIA/AMD ECCPUConnector, 0.30.0rc1 for Ascend ECExampleConnector, 0.5.10 for SGLang); admission does not enforce it.
  • Group-forward probe: Verified on vLLM 0.25.1/0.29.0 (cmpl- + request_id) and SGLang 0.5.18/0.5.21 (meta_info.id = rid). On other releases, the probe still runs: Verified admits a member, Unknown keeps prior eligibility, and only a failed health check withdraws it (Endpoint status ).

Transport compatibility

The shared-store path uses KVCacheBackend.spec.transport.protocol. The direct PD path selects Mooncake, NIXL or HIXL through spec.kvTransfer.backend (Direct KV transports ). Admission refuses deployments whose store and direct paths request incompatible fabrics.

Transport (API/Mooncake) Engine Store path
TCP / tcp vLLM Works, default images; beside a direct path it keeps its store connections open and did not run out of ports where measured
TCP / tcp SGLang Works, with a store image on its client’s line ; beside a direct path, it runs out of ports unless model-deployment-tcp-tw-reuse is on
TCP / tcp vLLM-Ascend Not supported: refused at admission; store client accepts CANN only
RDMA / rdma vLLM Not verified
RDMA / rdma SGLang Not verified
RDMA / rdma vLLM-Ascend Not supported: refused at admission, as for TCP
EFA / efa vLLM Own image: requires an EFA build of Mooncake in the engine; default store image
EFA / efa SGLang Not supported: no EFA build serves SGLang
EFA / efa vLLM-Ascend Not supported: refused at admission, as for TCP
CANN / ascend vLLM Not supported: CUDA client has no Ascend transport
CANN / ascend SGLang Not verified
CANN / ascend vLLM-Ascend Not verified; members need an image carrying CANN
ROCM / hip vLLM, SGLang Not verified
ROCM / hip vLLM-Ascend Not supported: refused at admission, as for TCP
MUSA, MACA / musa, maca vLLM, SGLang, vLLM-Ascend Not verified

Direct-path observations apply only to the named configurations:

  • Mooncake TCP: Verified on default vLLM and SGLang images. SGLang can exhaust ephemeral ports unless model-deployment-tcp-tw-reuse is enabled.
  • Mooncake RDMA: Verified with vLLM on InfiniBand H100 SXM5 in Prefill and Decode Benchmark and Encode, Prefill and Decode Benchmark .
  • EFA: Requires an EFA engine build (default store image includes EFA). Combined store and direct EFA paths are unverified.
  • vLLM-Ascend direct: Verified on cann9.1-910b-vllm0.23.0 behind llm-d-router. Stores on Ascend require CANN members (image carrying CANN ).

Remote weight loading

--load-format model-transfer loads verified tensors from a prepared remote source while keeping each engine’s parameter mapping and sharding. vLLM and vLLM-Ascend use the vLLM general load-format plugin; SGLang uses .pth CLI and LoadFormat hooks. See Remote Weight Delivery for configuration.

Engine Adapter entry Qualification state
vLLM NativeModelTransferLoader, --load-format model-transfer on CUDA H100 loading and inference observed for full-resident and paged 80B sources and full-resident 235B broadcast; production qualification remains open
vLLM-Ascend NativeModelTransferLoader through vLLM general plugin with vllm_ascend (requires CANN 9.2+ image with Python hixl, e.g. cann9.2-910b-vllm0.30.0) Loading and inference measured on two Ascend 910B2 nodes for Qwen3-8B, Qwen3.6-35B-A3B and Qwen3-235B-A22B-W8A8; managed HIXL admitted by default; production qualification remains open
SGLang NativeSGLangModelTransferLoader, --load-format model-transfer via .pth CLI and LoadFormat hooks (requires CANN 9.2+ image on Ascend for Python hixl) H100 80B loading and inference observed; Ascend covers CLI, LoadFormat, probe and session-open, with full loading qualification open

A CUDA capture does not qualify Ascend or ROCm. Under delivery policy Require, an unqualified engine and pool combination blocks instead of falling back.

Ascend (HIXL)

See Ascend benchmark for same-node and cross-node load times. CANN 9.2 adds Python hixl (/usr/local/Ascend/cann-9.2.0/python/site-packages/hixl) beside libcann_hixl.so; CANN 9.0 images lack Python hixl, so load_runtime() fails closed with RuntimeUnavailableError.

Limitations

  • SGLang store RAM: SGLang with a store enables --enable-hierarchical-cache (or --disaggregation-decode-retraction-backup cpu_tensor on Decode) and allocates pinned host RAM. Size node RAM above the engine heap plus that pool (KV Cache Pools and Bindings ).
  • SGLang PD TCP port exhaustion: SGLang Prefill opens a new TCP connection per transfer to Decode and each store member. Ephemeral sockets left in TIME-WAIT exhaust container ports, after which requests fail (503 No available prefill workers without a store) until engine Pods restart.
  • Mitigation (model-deployment-tcp-tw-reuse): Prevented exhaustion across 1,905 sequential requests on SGLang 0.5.18 with a store (~19,500 TIME-WAIT sockets). First add allowedUnsafeSysctls: ["net.ipv4.tcp_tw_reuse"] to KubeletConfiguration on every eligible node (otherwise Prefill Pods fail with SysctlForbidden), then patch the Setting:
bash
kubectl -n gpustack-system patch setting model-deployment-tcp-tw-reuse \
  --type merge -p '{"spec":{"value":"true"}}'
  • Untested boundaries: The store-free SGLang pair was not tested with tcp_tw_reuse, widening ip_local_port_range only delays exhaustion, and fabric transport avoidance is unverified.
  • vLLM comparison: vLLM reuses transfer connections and held at most 9 TIME-WAIT sockets without a store and at most 16 with a TCP store.
