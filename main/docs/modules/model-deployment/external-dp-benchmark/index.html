External DP Benchmark

On one eight-GPU H100 SXM5 node, wide tensor parallelism (TP) delivered 2.27×–6.99× higher output throughput than External DP over TCP across all twelve matched cells. External DP had lower median first-token latency at concurrency 64 on both shapes, while both eight-GPU configurations completed 1,088/1,088 measured requests with zero errors.

Both ran deepseek-ai/DeepSeek-V2-Lite-Chat, a mixture of experts (MoE) model. Wide TP kept all eight GPUs inside one NVLink Pod; External DP ran four two-GPU Pods with NVLink for local TP and TCP for the cross-Pod expert collective. External DP defines the serving contract.

The initial suites describe cross-Pod TCP. The separate InfiniBand RDMA comparison records the matched follow-up.

Summary

  • Choose wide TP on single-node NVLink when throughput and token-generation latency dominate.
  • Choose External DP when per-rank HTTP ingress or concurrency-64 first-token latency fits the workload (especially with InfiniBand RDMA, where it also led concurrency-64 output).

Benefits

  • Registered four healthy endpoints and balanced traffic evenly (285 + 284 × 3).
  • Lowered concurrency-64 TTFT p50 by 2.58× at 1024/256 and 1.23× at 4096/128.
  • Completed 1,088/1,088 measured requests in both configurations with zero errors.

Trade-offs

  • Over TCP, wide TP delivered 2.27×–6.99× higher output throughput in all twelve cells.
  • Cross-Pod EP used TCP versus single-Pod NVLink for wide TP.
  • At 4096/128, concurrency 64 over TCP, External DP suffered severe TTFT p95 and ITL p99 tails.

Configuration

Each configuration ran one ModelDeployment on gpu-node-0.

Configuration Roles Pods GPUs per Pod Router
Wide TP 1 Server 1 8 None; direct engine HTTP
External DP 1 Server group 4 2 vllm-router, round_robin

Wide TP set --tensor-parallel-size 8 without --enable-expert-parallel. External DP set data parallelism (DP) = 4, local TP = 2 and expert parallelism (EP) enabled (--all2all-backend allgather_reducescatter), with one API server and local attention KV cache per rank and no cross-rank KV transfer.

NVLink carried intra-Pod traffic only. Each Pod had private IPC and /dev/shm, hostIPC disabled and no remote direct memory access (RDMA) interface, so cross-Pod EP communication used TCP sockets over eth0.

Port allocation

Every External DP rank set VLLM_PORT=19500, and the run initialized on port 19502 (an observed choice, not a fixed offset). See Port allocation for vLLM port probing and the bootstrap-port race, and the walkthrough manifest .

Workload

Target prompt/output shapes were 1024/256 and 4096/128 at concurrency 1, 4, 8, 16, 32 and 64 (32, 32, 32, 64, 128 and 256 measured requests per shape, plus four excluded warm-ups per cell and one calibration request per configuration). Prompts carried unique markers, and early stopping varied output-token totals.

Measurement method

The in-cluster streaming generator ran each configuration once, sequentially, with warmed weights (2,176 measured requests across 24 result files). Output throughput divides actual generated tokens by cell wall time.

Time to first token (TTFT), time per output token (TPOT) and inter-token latency (ITL) use captured millisecond precision. Bold values mark lower latency or higher throughput within each matched pair without claiming statistical significance.

Results

Latency and throughput

Every cell completed with zero errors.

Over TCP against single-Pod NVLink wide TP, wide TP won output throughput in all 12 cells by 2.27×–6.99× (peaking at 2,647.004 tok/s versus 436.861 tok/s at 1024/256, concurrency 16; External DP peaked at 1,017.434 tok/s at concurrency 64) and kept 6.9×–7.3× lower TPOT p50 at concurrency 1.

External DP beat wide TP on TTFT p50 only at concurrency 64 (2.58× lower at 1024/256: 1,863.100 versus 4,798.411 ms; 1.23× lower at 4096/128: 3,094.017 versus 3,814.139 ms), where 4096/128 tails degraded (TTFT p95 17,594.349 versus 4,057.352 ms; ITL p99 1,953.899 versus 55.619 ms). Parallelism, transport, routing and API-server count changed together, so individual causes are not isolated.

InfiniBand RDMA comparison

A follow-up on the ConnectX-7 InfiniBand node from Prefill and Decode Benchmark kept DP = 4, TP = 2 per Pod, one API server per rank and round_robin routing. All twelve cells completed 1,088/1,088 requests with zero errors.

Transport performance

In this separate InfiniBand follow-up (where wide TP was not rerun), RDMA External DP cut concurrency-64 TTFT p50 by 6.26× (1024/256) and 8.47× (4096/128) over TCP, raised output 3.85× and 7.01×, and cut 4096/128 tails (TTFT p95 17,594.349 → 1,477.799 ms; ITL p99 1,953.899 → 182.693 ms).

Exceptions remain: wide TP kept higher output at concurrencies 1–32 (10 of 12 cells) and lower TPOT p50 and ITL p99 in all 12 cells, and RDMA regressed ITL p99 versus TCP at 1024/256, concurrency 8 (26.162 to 64.911 ms).

Wide tensor parallelism

At concurrency 64 (separate runs, eight GPUs each), RDMA External DP beat the recorded wide-TP output throughput on both shapes (1.69× at 1024/256 and 1.36× at 4096/128) and cut TTFT p50 16.13× and 10.44×. Wide TP still kept lower ITL p99 in both cells.

Routing verification

Role status confirmed four serving endpoints for one replica group. Engine completion counts matched 285 + 284 + 284 + 284 = 1,137 (1,088 measured, 48 warm-ups, one calibration), proving traffic reached every rank.

RDMA trade-offs

  • Choose RDMA External DP when high-concurrency ingress (concurrency 64) and first-token latency outweigh smoother token generation.
  • Choose wide TP on single-node NVLink for concurrencies 1–32 throughput and the lowest TPOT p50 and ITL p99 across every concurrency (including 55.619 versus 182.693 ms at 4096/128, concurrency 64).

No repeated trials isolate the 1024/256, concurrency-8 RDMA ITL p99 regression (64.911 versus 26.162 ms TCP). Cross-node behavior, other models and other backends remain unmeasured.

Limitations

  • One run per configuration (32–256 requests per cell) provides no repeated-run confidence intervals.
  • Batching limits were per engine: four rank API servers differ from one wide API server.
  • Parallelism, transport and routing changed together; no single overhead term was isolated.
  • Neither capture measures cross-Pod NVLink, and separate runs do not isolate transport from run-to-run variation.
  • All ranks shared one GPU node; cross-node placement, other DP widths and online resizing were not measured.
  • Only one MoE model and two prompt shapes ran; dense-model behavior cannot be inferred.
  • Unique prompt markers and early stopping varied prompt and generated-token totals slightly.
  • Direct nonstreaming rank probes and a released-device snapshot were omitted from the TCP capture.
