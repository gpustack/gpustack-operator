Encode, Prefill and Decode Walkthrough

Deploy Qwen/Qwen2.5-VL-7B-Instruct across dedicated Encode, Prefill, and Decode roles behind llm-d-router, inspect rendered NIXL encoder-cache flags, and verify multimodal completion across all three stages.

Summary

Encode/prefill/decode (EPD) disaggregation isolates multimodal vision encoding onto Encode Pods so large image bursts do not stall token generation. Text-only requests traverse Prefill → Decode, while multimodal requests route through Encode → Prefill → Decode (Encode, Prefill and Decode ):

Object Scope Creator Purpose
ModelArtifact namespace user Resolves Qwen/Qwen2.5-VL-7B-Instruct weights
ModelPrefetch namespace user Warms qwen2-5-vl-7b-instruct onto the H100 node
AcceleratorType cluster operator H100 pool requested by all three roles
ModelDeployment namespace user Runs 1 Encode, 1 Prefill, and 1 Decode replica behind llm-d-router
Router Deployment and Service namespace operator Single HTTP endpoint routing multimodal and text requests

In the H100 benchmark (3 GPUs for EPD vs 2 for PD and 1 for aggregated serving), EPD improved concurrency-8 4k/8k inter-token latency (ITL) p99 by 15.1×–21.8× and repeated-image time to first token (TTFT) p50 by 5.9×, while small-prompt TTFT often favored aggregated serving; see Encode, Prefill and Decode Benchmark .

Environment

Item Value
Cluster Kubernetes v1.35.7; 1 CPU node and 1 GPU node (gpu-node-0)
GPUs 8 × NVIDIA H100 80 GB HBM3 SXM5 (3 GPUs allocated: 1 per role)
Pool Captured on custom InstanceType bench-gpu; reusable manifest uses gpustack--nvidia-h100-80gb-hbm3-linux-amd64
Model Qwen/Qwen2.5-VL-7B-Instruct from ModelArtifact qwen2-5-vl-7b-instruct mounted at /var/lib/gpustack/model
Runtime vLLM gpustack/runner:cuda13.0-vllm0.30.0 with llm-d-router

Deployment

Step 1: Start three-role serving

Create and prefetch ModelArtifact qwen2-5-vl-7b-instruct in gpustack-bench using Model Prefetch , then save epd-deployment.yaml:

yaml
apiVersion: worker.gpustack.ai/v1
kind: ModelDeployment
metadata:
  name: epd-arm3-epd
  namespace: gpustack-bench
spec:
  model:
    name: qwen2-5-vl-7b-instruct
    artifactRef:
      name: qwen2-5-vl-7b-instruct
  engine:
    name: vLLM
    image: gpustack/runner:cuda13.0-vllm0.30.0
  router:
    name: llm-d-router
  roles:
    - name: encode
      kind: Encode
      replicas: 1
      size: 1
      acceleratorType: gpustack--nvidia-h100-80gb-hbm3-linux-amd64
      image: gpustack/runner:cuda13.0-vllm0.30.0
      imagePullPolicy: IfNotPresent
      resources:
        accelerator: "1"
      extraArgs:
        - --max-model-len
        - "16384"
        - --gpu-memory-utilization
        - "0.85"
    - name: prefill
      kind: Prefill
      replicas: 1
      size: 1
      acceleratorType: gpustack--nvidia-h100-80gb-hbm3-linux-amd64
      image: gpustack/runner:cuda13.0-vllm0.30.0
      imagePullPolicy: IfNotPresent
      resources:
        accelerator: "1"
      extraArgs:
        - --tensor-parallel-size
        - "1"
        - --max-model-len
        - "16384"
        - --gpu-memory-utilization
        - "0.85"
    - name: decode
      kind: Decode
      replicas: 1
      size: 1
      acceleratorType: gpustack--nvidia-h100-80gb-hbm3-linux-amd64
      image: gpustack/runner:cuda13.0-vllm0.30.0
      imagePullPolicy: IfNotPresent
      resources:
        accelerator: "1"
      extraArgs:
        - --tensor-parallel-size
        - "1"
        - --max-model-len
        - "16384"
        - --gpu-memory-utilization
        - "0.85"

Apply epd-deployment.yaml and wait for ROLES=1R1E1P1D and PHASE=Ready:

bash
kubectl apply -f epd-deployment.yaml
kubectl get modeldeployment epd-arm3-epd -n gpustack-bench \
  -o custom-columns=NAME:.metadata.name,ENGINE:.spec.engine.name,ROLES:.status.roleSummary,PHASE:.status.phase
kubectl get pods -n gpustack-bench -l app.kubernetes.io/instance=epd-arm3-epd

    ports: [.spec.containers[0].ports[]?.containerPort],
    proxyArgs: (.spec.initContainers // [] | map(select(.name=="routing-proxy"))[0].args)

Confirm three rendered invariants:

  • Encode runs --mm-encoder-only (keeping LLM weights unloaded), defaults --enforce-eager and --no-enable-prefix-caching (Operator-owned keys ), defaults NIXL side-channel port 5601 (VLLM_EC_SIDE_CHANNEL_PORT=5601, overridable including 0), and defaults VLLM_USE_V2_MODEL_RUNNER=1 on vLLM < 0.34.0 (omitted at >= 0.34.0).
  • Prefill pairs ECCPUConnector (ec_consumer) with MooncakeConnector (kv_producer) while keeping CUDA graphs enabled.
  • Decode serves behind routing-proxy on :8000 (--ec-connector=ec-nixl → engine :8200).

Verification

Step 3: Send a multimodal request

Read status.endpoint and send a multimodal chat completion containing both an image_url (base64 PNG) and a text prompt for "model": "qwen2-5-vl-7b-instruct":

bash
kubectl get modeldeployment epd-arm3-epd -n gpustack-bench -o jsonpath='{.status.endpoint}{"\n"}'

Captured output:

text
http://epd-arm3-epd-router.gpustack-bench.svc:8000

Step 4: Check admission and placement

Confirm that Kueue reserved all three role Workloads together:

bash
kubectl get workloads -n gpustack-bench

All four Pods ran on gpu-node-0, with private IPC, private /dev/shm, and no RDMA interface; all cross-Pod NIXL encoder-cache and Mooncake KV transfers used TCP over eth0.

Across multi-node clusters, rendered soft Pod affinity weights prefer co-locating roles that exchange the largest payloads without blocking scheduling (Role placement preferences ):

Replica Preferred peer Weight
Encode Prefill 50
Prefill Decode 100
Prefill Encode 50
Decode Prefill 100

Cleanup

Delete epd-arm3-epd and wait until all owned Pods and Services terminate:

bash
kubectl delete modeldeployment epd-arm3-epd -n gpustack-bench
kubectl get pods,services -n gpustack-bench -l app.kubernetes.io/instance=epd-arm3-epd

Limitations

  • Role kinds (Encode, Prefill, Decode, Server) are frozen after creation.
  • Measurements cover single-node TCP transfer.
  • Retiring an Encode replica drains for a fixed ~300 s window because encoders expose no in-flight request counter; transfers still active when that window expires fail at the client.

Troubleshooting

Symptom Signal Resolution
Apply rejected on role structure Webhook refusal on ModelDeployment Encode requires both Prefill and Decode (one role per kind, no Server, no spec.kvCache, and no role command; see Admission constraints ).
Apply rejected on engine, router, or platform Webhook refusal on ModelDeployment All three roles must share one accelerator platform and match Supported serving configurations (vllm-router is rejected on Ascend).
Encoder container exits on unknown flag Container startup failure Upgrade the runner image to meet the floor (vLLM >= 0.30.0, vllm-ascend >= 0.30.0rc1, SGLang >= 0.5.10; see Engine Compatibility ).
Requests bypass Prefill Router routes directly to Decode Check vLLM token-counting support and --enable-scale-out rules (Router token counting ).
Ascend encoder fails storage setup ECExampleConnector missing shared path Mount a shared ReadWriteMany PVC on both Encode (read-write) and Prefill with identical claimName, mountPath, and subPath.
Apply rejected on port 5601 or 8997 Side-channel or bootstrap port collision ECCPUConnector defaults VLLM_EC_SIDE_CHANNEL_PORT=5601 (override in roles[].env, including 0, or move HTTP off 5601), and SGLang Prefill in EPD owns 8997.
Encode replica stays in Draining ~300 s Bounded encoder drain timer Expected behavior; wait for the ~300 s drain window to finish.
RoleKindsReady=False Zero Ready replicas in one role kind Read the failing kind from ModelDeployment status and inspect its Pod events and container logs.
